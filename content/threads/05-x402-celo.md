# Thread 5: Selling to agents on Celo with x402

1/
Your API's next customer won't sign up, won't take an API key, and won't pay an invoice.

It's an agent.

Here's how to sell to it on Celo in 2026, with x402 v2 🧵

2/
The flow:

1. Agent calls your endpoint
2. You answer 402 with a price (PAYMENT-REQUIRED header)
3. Agent signs a gasless USDC authorization (EIP-3009)
4. Retries with PAYMENT-SIGNATURE
5. You do the work; the facilitator settles

The request is the transaction.

3/
The 2026 stack:

• @x402/next, @x402/core, @x402/evm (2.27.0)
• Celo mainnet = eip155:42220 (CAIP-2)
• USDC on Celo: 0xcebA…118C
• Facilitator: api.x402.celo.org (it pays gas, never holds funds)

Skip the old unscoped x402-* 1.x packages. v1, no Celo.

4/
The detail that matters most: withX402 only settles if your handler answers below 400.

Errors, timeouts, model outages: never charged.

We lean on that: if our decision model is down, the paid route returns 503 instead of guessing.

5/
Mind the fee: the hosted facilitator charges ~$0.001 per settlement.

A $0.001 call nets you nothing. Price at $0.01+, or self-host a facilitator for sub-cent pricing.

6/
Discovery, so agents can find you:

• llms.txt listing every paid route + price
• A2A agent card at /.well-known/agent-card.json
• ERC-8004 identity on Celo (registration-v1 shape)

7/
3 mistakes I found in my own old hackathon code:

• charging before calling upstream (billing for failures)
• a "fallback" serving content without settling
• a demo swarm paying its own treasury in a loop 🙃 (inflated volume + poisoned reputation)

Fixing all three this week.

8/
